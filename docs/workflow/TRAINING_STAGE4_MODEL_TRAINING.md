# TRAINING STAGE 4: Обучение модели (Model Training)

Цель этапа: обучить выбранную модель (`prophet` или `xgboost`) на подготовленном датасете и получить предсказания/метрики для контроля качества.

---

## 1. Что делает этап

Stage 4:
- выбирает trainer по `model_type`;
- применяет `train_params`;
- обучает модель на очищенных данных;
- строит валидационные предсказания;
- подготавливает метрики и артефакт модели для Stage 5.

---

## 2. Входной контракт

Из Stage 3 приходит:
- preprocessed DataFrame;
- `model_type`;
- `train_params`;
- контекст объекта (`object_reference`) для идентификации run.

Ожидается:
- стабильный ряд без критических пропусков;
- достаточный размер выборки.

---

## 3. Обязательный базовый шаг: линейная регрессия (baseline)

Перед обучением Prophet или XGBoost **всегда** нужно обучить интерпретируемую baseline-модель на основе линейной регрессии.

Зачем:
- даёт нижнюю планку качества — если Prophet/XGBoost не превышает baseline, значит что-то пошло не так;
- легко объясняет результат заказчику (коэффициенты = вклад каждого признака);
- быстро обучается и не требует тюнинга.

Типовой сценарий:
1. Построить минимальный feature-набор: час суток (one-hot или sin/cos), день недели, лаги `t-1`, `t-24`, `t-168`;
2. Обучить `LinearRegression` (или `Ridge`) на train-подмножестве;
3. Рассчитать те же метрики, что для основной модели: MAE, MAPE, RMSE;
4. Зафиксировать результат в MLflow с тегом `model_type=linear_baseline`.

Пример:
```python
from sklearn.linear_model import Ridge

model_baseline = Ridge()
model_baseline.fit(X_train, y_train)
preds_baseline = model_baseline.predict(X_test)
# логировать mae/mape/rmse в MLflow с тегом model_type=linear_baseline
```

Критерий перехода дальше: основная модель (Prophet или XGBoost) должна стабильно превышать baseline хотя бы по одной метрике; в противном случае — пересмотреть preprocessing или гиперпараметры.

---

## 4. Ветка Prophet

Типовой сценарий:
1. создать объект Prophet с параметрами из `train_params`;
2. вызвать `fit(df)`;
3. сформировать future DataFrame;
4. получить forecast для оценки качества.

Пример параметров:
- `changepoint_prior_scale`
- `seasonality_mode`
- `yearly_seasonality`
- `weekly_seasonality`
- `daily_seasonality`

Когда использовать:
- выраженная сезонность;
- нужна интерпретируемость тренда/сезонов;
- устойчивый таймстамп-ряд.

---

## 5. Ветка XGBoost

Типовой сценарий:
1. построить lag-features (`t-1`, `t-2`, `t-24`, `t-168`, ...);
2. разделить данные на train/test;
3. создать `XGBRegressor` с `train_params`;
4. выполнить `fit(X_train, y_train)`;
5. получить тестовые предсказания.

Пример параметров:
- `n_estimators`
- `max_depth`
- `learning_rate`
- `subsample`
- `colsample_bytree`

Когда использовать:
- сильная нелинейность;
- большое количество данных;
- важна скорость инференса после обучения.

---

## 6. Что считается выходом Stage 4

На Stage 5 передается:

```json
{
  "model": "trained model object",
  "model_type": "prophet|xgboost",
  "predictions_validation": "array/dataframe",
  "y_validation": "array",
  "train_params_applied": {"...": "..."}
}
```

Примечание:
- финальная публикация артефакта и формальных метрик выполняется на Stage 5 в MLflow.

### 5.1 Practical notebook note

Для ручного retraining этот этап может выполняться в `TRAINING_MANUAL_WORKFLOW.ipynb`.

Рекомендуемый формат результата для каждого candidate block в notebook:
- `model_name`;
- `status`;
- `fit_time_sec`;
- `metrics` (`mae`, `mape`, `rmse`);
- `train_params`;
- `notes`.

Такой единый output позволяет сравнивать Prophet, XGBoost и будущие алгоритмы без переписывания comparison/report sections.

## 7. Ошибки и риски

Частые проблемы:
- недостаточно данных после Stage 3;
- плохая сходимость Prophet;
- переобучение/нестабильность XGBoost;
- некорректные гиперпараметры (например, отрицательные значения);
- memory pressure при больших выборках.

Рекомендации:
- валидировать диапазоны гиперпараметров до fit;
- ограничивать размер обучающего окна;
- логировать train/test размер и время fit.

## 8. Мини-матрица выбора модели

| Условие | Предпочтение |
|---|---|
| Явная сезонность и explainability | Prophet |
| Нелинейные зависимости и высокая вариативность | XGBoost |
| Малый набор признаков и простой ряд | Prophet |
| Богатая feature-инженерия | XGBoost |

1. Убедиться, что trainer выбран согласно `model_type`.
2. Проверить, что fit завершился без исключений.
3. Получить валидационные предсказания и базовые метрики.
4. Проверить, что модель-объект сериализуем для Stage 5.

- модель успешно обучена;

- есть валидный model object для логирования в MLflow на Stage 5.
