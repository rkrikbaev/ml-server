# TRAINING STAGE 3: Предобработка данных (Data Preprocessing)

Цель этапа: очистить и стандартизировать сырой датасет из Stage 2, чтобы он стал пригоден для стабильного обучения модели.

---

## 1. Что делает этап

Stage 3 выполняет:
- выделение целевых колонок;
- сортировку по времени;
- удаление дубликатов;
- обработку пропусков;
- базовую фильтрацию выбросов;
- форматирование признаков под выбранный тип модели;
- финальную валидацию набора.

---

## 2. Базовый pipeline преобразований

```text
raw df
  -> keep [date_column, target_column]
  -> sort by date_column
  -> drop duplicates
  -> parse timestamps
  -> fill missing values
  -> optional outlier filter (IQR)
  -> feature formatting for model_type
  -> final sanity checks
```

---

## 3. Типовые операции

### 3.1 Выделение колонок
Оставляются только необходимые поля:
- дата/время (`date_column`)
- целевой ряд (`target_column`)

### 3.2 Сортировка
Хронологический порядок обязателен для time-series обучения.

### 3.3 Дедупликация
Повторяющиеся timestamps удаляются.

### 3.4 Валидация времени
Поле времени приводится к datetime/ISO-формату.

### 3.5 Обработка пропусков
Обычно применяется комбинация:
- forward-fill
- backward-fill

### 3.6 Выбросы
Опционально удаляются/ограничиваются через IQR-правило.

### 3.7 Подготовка под модель
- для Prophet колонки обычно приводятся к `ds` и `y`;
- для XGBoost остаются числовые признаки + целевой столбец.

### 3.8 Финальная валидация
Примеры минимальных проверок:
- `len(df) > min_rows`;
- нет критических NaN в целевой переменной;
- временной индекс монотонный.

---

## 4. Пример трансформации

До:

```text
timestamp               value      note
2025-01-01 00:00        1234.5     ok
2025-01-01 00:00        1234.5     duplicate
2025-01-01 01:00        NaN        missing
2025-01-01 02:00        999999.0   outlier
2025-01-01 03:00        1201.3     ok
```

После:

```text
ds                      y
2025-01-01 00:00        1234.5
2025-01-01 01:00        1234.5
2025-01-01 02:00        1234.5
2025-01-01 03:00        1201.3
```

---

## 5. Ошибки этапа

Типовые причины падения:
- после очистки осталось слишком мало строк;
- временная колонка не парсится;
- target-колонка не числовая/сильно повреждена;
- весь ряд состоит из NaN/константных значений.

Реакция:
- завершить обучение с диагностикой причины;
- вернуть понятное сообщение для оператора/клиента;
- сохранить контекст в логах (counts before/after, missing ratio, outlier ratio).

---

## 6. Выход этапа

В Stage 4 передается clean dataset:

```json
{
  "shape": "[rows, cols]",
  "columns": ["ds", "y"],
  "quality": {
    "missing_after": 0,
    "duplicates_removed": 123,
    "outliers_filtered": 45
  }
}
```

---

## 7. Проверка этапа

1. Проверить количество строк до/после обработки.
2. Убедиться, что нет NaN в целевом столбце.
3. Проверить корректность частоты ряда (`freq`) на выборке.
4. Для Prophet подтвердить наличие колонок `ds`/`y`.

---

## 8. Критерий готовности Stage 3

- данные очищены и валидны;
- структура совместима с выбранным trainer;
- pipeline готов перейти к Stage 4 (обучение).
