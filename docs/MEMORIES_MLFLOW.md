
1. Схема хранения (Storage)
Мы используем гибридный подход для надежности и производительности:
Backend Store: sqlite:///mlflow_data/mlflow.db — хранит метрики, параметры, теги и метаданные входных данных.
Artifact Store: ./mlflow_data/artifacts — хранит тяжелые объекты (модели, сериализованные датасеты, графики).
2. Концепция "Паспорта данных"
Чтобы модель знала, откуда брать данные при прогнозе, мы используем механизм Tags (Теги).
Процесс:
Обучение: В объект mlflow.set_tag записывается JSON-конфигурация источника (тип БД, SQL-запрос, пути в S3).
Запуск прогноза:
Программа считывает run_id модели.
Запрашивает из SQLite значение тега data_source_config.
Передает этот конфиг в модуль сбора данных (data_loader).
Полученный DataFrame подается на вход загруженной модели.
3. Структура проекта
text
project_root/
│
├── mlflow_data/           # Единое хранилище (в .gitignore)
│   ├── mlflow.db          # База метаданных
│   └── artifacts/         # Папки экспериментов и моделей
│
├── src/
│   ├── train.py           # Логирует параметры и "паспорт данных"
│   └── predict.py         # Считывает теги и запускает сбор данных
│
└── run_server.sh          # Команда запуска:
                           # mlflow server --host 0.0.0.0 --port 5000 \
                           # --backend-store-uri sqlite:///mlflow_data/mlflow.db \
                           # --default-artifact-root ./mlflow_data/artifacts
Используйте код с осторожностью.
4. Ключевые преимущества
Автономность: Модель сама "рассказывает" системе прогнозирования, какие данные ей нужны.
Масштабируемость: SQLite позволяет быстро фильтровать сотни запусков.
Прозрачность: Всегда можно восстановить цепочку: Какая модель -> На каком запросе обучалась -> Какие метрики получила.
